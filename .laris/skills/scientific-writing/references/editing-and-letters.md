# Editing, style, cover letters, and reviewer responses

## Style rules
- Concise, active academic style; one idea per paragraph; topic sentence first.
- Consistent terminology: pick one term per concept and keep it (record in notation-and-conventions.md).
- Claims calibrated to evidence; hedge only where evidence is limited, and say why.
- Introduction arc: context -> problem -> what exists (verified refs) -> gap -> contribution list -> outline.
- Limitations stated plainly in Discussion or Conclusion.

## Three editing levels
1. Fix errors: grammar, typos, notation inconsistencies, broken references.
2. Rewrite sentences: clarity, concision, flow; meaning unchanged.
3. Restructure: reorder sections/paragraphs, merge or split, change argument flow.
Always deliver a change log: location, level, what changed, why. For docx, tracked changes via the docx
skill when the user wants them.

## Cover letter (default docx unless the venue requires another form)
Editor name if known (verified) or "Dear Editor"; title and article type; one-paragraph contribution
summary; fit with the venue's scope (verified wording, paraphrased); statements required by the venue
(originality, no concurrent submission, conflicts); suggested reviewers only if requested by the venue.

## Point-by-point response letter
For each comment: quote the comment (verbatim from the decision letter), then:
- Response: agree / partially agree / respectfully disagree.
- Action: what changed, with location (section, page, line) and the new text if short.
- Evidence: for a rebuttal, give data, derivation, or verified references; never dismiss without evidence.
Tone: courteous, specific, no defensiveness. Escalate drafting of responses to Opus 5.5 high.
Route: docx by default; LaTeX if the journal template requires it (via the LaTeX route).
